**Fixes a crash on launch in v0.1.0. If you have v0.1.0, replace it.**

### The crash

v0.1.0 segfaulted on launch on any Mac where something had already set the clamshell sleep bit —
a previous run that was interrupted, a second copy of the app, or another keep-awake utility.
`EXC_BAD_ACCESS` at `0x94` on the main thread.

Lidwing was showing a modal alert from inside `applicationDidFinishLaunching`, which runs inside
the Apple Event handler. The nested modal run loop popped an autorelease pool that the launch
machinery still owned.

The launch path now never opens a dialog. The condition is still unmissable — the menu bar glyph
shows it, the menu says it in words, and `Repair Now…` is there when you want it. The
confirmation dialog moved to that menu item, where the ellipsis was already promising one.

That path is not rare, and that is the point: the clamshell bit is global, owned by nobody and
carries no reference count, so a crashed instance or a competing utility leaves a Mac in exactly
this state.

### Also in this build

- **The watchdog retires.** `lidwingd` used to be restarted by launchd forever, so after the app
  quit or crashed it stayed running with nothing to watch. It now exits once there is no app left
  **and** the machine is provably back to normal — and still comes straight back if it dies while
  guarding an armed session.
- **English only.** v0.1.0 shipped a Russian catalogue selected from your system language, so on
  a Russian-language Mac the interface was Russian. That was never intended. The translation and
  the mechanism that chose it are both gone, and a test now fails if any shipped string contains
  a non-English letter. Text that comes from macOS itself — error messages, system dialog buttons
  — will still be in your language, and that is outside this app's control.
- **249 tests on macOS 15 and macOS 26**, 0 failures, 0 skipped.

### Still true from v0.1.0, and worth repeating

The mechanism is proven on **one** Mac for **twelve seconds**, with a positive control. There is
no 8-hour soak yet, no evidence about the powerd stomp on charger and display events, and nothing
at all on Intel, Air, fanless, T2, or any macOS other than 15.5. The app will tell you when it is
running on hardware nobody has tested it on.
