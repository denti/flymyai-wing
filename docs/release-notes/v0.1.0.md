**This is a pre-release for one person to try. It is not a launch.**

Lidwing keeps a MacBook awake with the lid closed so a local coding agent finishes its run, and
stops on its own before the battery dies or the Mac overheats.

### What is actually proven

- **The mechanism works on one Mac.** M0 short form, 2026-08-10, on a Mac14,2-class MacBook,
  macOS 15.5 (24F74), arm64, **on battery with no external display**: 36 heartbeat ticks, 12 of
  them with the lid shut, no gaps. With a positive control on the same machine — `pmset -g log`
  shows an ordinary lid close producing `Entering Sleep state due to Clamshell Sleep` half an
  hour earlier, and no clamshell sleep at all during the armed window.
- **It needs no privileges.** No admin password, no helper, no persistent system setting. The
  bit it sets is a kernel variable that a reboot clears unconditionally.
- **It declares nothing.** Zero `*UsageDescription` keys and zero entitlements — check with the
  two commands below.
- **244 unit tests on Linux, 249 on macOS 15 and macOS 26**, zero failures, zero skipped.
  The suite has been proven able to fail 31 different ways.
- **A watchdog holds the safety.** The app is the *client* of a separate process, so any death
  — including `kill -9` — closes a socket and the watchdog puts lid-close sleep back.

### What is not proven, and you should read this part

- **Twelve seconds, not eight hours.** The short form proves the clamshell demand-sleep does not
  fire. It says nothing about the powerd stomp on charger and display events, nothing about the
  dark-wake hole, and nothing about stability over a long run. The 8-hour soak has not happened.
- **One MacBook.** Nothing here has run on Intel, on an Air, on a fanless machine, on a T2 Mac,
  on M1/M2/M4, or on any macOS other than 15.5. **The app itself will tell you** when it is on
  hardware nobody has proven it on — that line in the menu is not decoration.
- **Nothing has been tested by anyone but its author and CI.** Fault injection, the performance
  numbers, the keyboard and VoiceOver pass: all written, none run on real hardware yet.
- **Low Power Mode is not in this build.** It needs a privileged helper and it is deliberately
  the only thing that will ever ask for a password. Not shipped rather than half-shipped.
- **Ad-hoc signed.** macOS will refuse it once; the steps are below.

### Known limitation

Closing the lid from the login window does nothing: an `LSUIElement` app is not running there.
Documented rather than fixed — fixing it would mean a resident process doing power work with no
user session, which is a much larger thing to ask you to trust.

### If something goes wrong

Open the menu, choose **Copy Diagnostics**, and send it. If your Mac will not sleep when you
close the lid and Lidwing is not running, **restarting clears it unconditionally** — Lidwing
never writes anything that survives a reboot.
